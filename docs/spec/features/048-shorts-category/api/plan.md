# PLAN: Shorts Category — `api` (`api/plan.md`)

## Scope

`api` owns everything in this feature except the screens: the `Movie.isShort` column and its
migration, the two new Settings catalog entries and seeds, the effective shorts capability, the
`asShort` registration path, the `setMovieShort` mutation, the `movies(isShort:)` filter, the
`isShort` field on every enriched search result, and the `path_shorts` branch in the encode job's
`outputRoot`.

It is **not** rendering anything: no badge, no toggle, no route gating, no Settings panel — `web`
owns all of that and reads the frozen contract. It is also not touching `services/worker/`: the
worker receives `outputRoot` as a resolved string and cannot tell a short from a feature film, which
is the whole reason the filing change fits in one branch here.

Writes are confined to `services/api/` and this directory. Anything else is a stop-and-report.

## Existing code to reuse

- `src/media/media-capabilities.service.ts` — the existing `read()` / `isEnabled()` /
  `assertEnabled()` / `enabledTypes()` shape, including its `map[key] !== 'false'` idiom and the
  comment explaining why. Extend it; do not write a second settings reader.
- `src/movies/movies.service.ts::enrichWithOwnership` — the single `movie.findMany` per results page
  that already attaches `mediaId`/`inLibrary`. `isShort` is one more entry in its `select`.
- `src/movies/movies.service.ts::findOneFromDb` — the ownership gate (`users: { some: { userId } }`)
  every per-title mutation runs before touching a row. `setShort` runs it too, and `setMovieShort`
  therefore returns `error.movie.not_found` for an unowned film with no second message
  (`docs/spec/graphql-contract.md` § `008-movie-detail`).
- `src/movies/movies.service.ts::setAudioMandatoryFor` — the shape of a single-column update behind
  an already-checked row. `setShort` is its structural twin, minus the `UserMovie` scoping, because
  `isShort` is a property of the film (spec REQ-1).
- `src/process-jobs/process-jobs.service.ts::resolveOutputRoot` — already the only place a
  destination is resolved, already raising `error.setting.missing` for an absent key and already
  validating through `MediaRootsService.resolveFromRoot('library', …)`. Widen its parameter type;
  do not add a second resolver.
- `src/settings/settings.catalog.ts` + `settings.service.ts::updateMany` — a `kind: 'path'` entry is
  validated against its root on write with no extra code here.
- `src/i18n/i18n-error.ts` (`i18nError.forbidden` / `.badRequest`) and `ERROR_KEYS` — the error
  envelope. Never throw a bare `ForbiddenException`.

## Steps

1. **Schema + migration.** Add `isShort Boolean @default(false)` to `model Movie`; run
   `bin/npm api run prisma:migrate` and commit both the schema change and the generated directory.
2. **Catalog + seeds.** Add the two entries to `SETTINGS_CATALOG` and the two rows to
   `prisma/seeds/settings.ts` (`shorts_enabled` = `'false'`, `path_shorts` = `'Shorts'`).
3. **`MediaCapabilitiesModule`.** New module in `src/media/` declaring and exporting
   `MediaCapabilitiesService`, importing only `SettingsModule`. Remove the service from
   `MediaModule`'s `providers` and import the module there instead. **No `forwardRef` anywhere** —
   if one seems necessary, the split was done wrong; stop and report.
4. **The capability itself.** `read()` returns a third field. `shortsEnabled` is
   `moviesEnabled && map['shorts_enabled'] === 'true'` — note the `=== 'true'`, which is the
   **opposite** of the `!== 'false'` idiom used two lines above it for movies and series, and it is
   deliberate: an absent row must read as *off* so an install that predates this feature does not
   grow a category nobody enabled (spec NFR-3, `../plan.md` § Risks). Add `isShortsEnabled()` and
   `assertShortsEnabled()`, the latter throwing `i18nError.forbidden(ERROR_KEYS.MEDIA_SHORTS_DISABLED)`.
   Update the entity with `shortsEnabled: Boolean!`.
5. **Error keys.** `MEDIA_SHORTS_DISABLED: 'error.media.shorts_disabled'` and
   `MEDIA_SHORTS_NOT_A_MOVIE: 'error.media.shorts_not_a_movie'` in `error-keys.ts`, with English
   renderings in `messages.en.ts` (`'Shorts are disabled on this system'` / `'Only a film can be
   registered as a short'`).
6. **`addMedia(asShort:)`.** Add the nullable `Boolean` argument to `MediaResolver.addMedia`. Order
   of guards, before any service runs: existing `assertEnabled(type)` → if `asShort` and
   `type !== MEDIA_TYPE.MOVIE`, `i18nError.badRequest(ERROR_KEYS.MEDIA_SHORTS_NOT_A_MOVIE)` → if
   `asShort`, `assertShortsEnabled()`. Then `dispatch.resolve(type).register(tmdbId, userId, { asShort })`.
7. **The interface.** `MediaTypeService.register` gains an optional
   `options?: { asShort?: boolean }`. `MoviesService.register` reads it and passes
   `isShort: options?.asShort === true` into `create()`; `ShowsService.register` keeps its two-parameter
   signature untouched (a narrower implementation satisfies the interface, and step 6 guarantees a
   show never reaches it with the flag set). An existing film short-circuits before `create()` as it
   does today — registering an already-registered film as a short does **not** rewrite the flag; the
   detail-page toggle is the way to change it (spec REQ-6).
8. **`setMovieShort`.** `MoviesService.setShort(id, userId, isShort)`: `findOneFromDb(id, userId)`
   first, `error.movie.not_found` when it returns null, then `movie.update`. Expose it on
   `MoviesResolver` as `setMovieShort(movieId: Int!, isShort: Boolean!): Movie!`, guarded by
   `assertEnabled(MEDIA_TYPE.MOVIE)` then `assertShortsEnabled()` — in that order, so a caller with
   movies disabled gets `error.media.type_disabled`, matching the spec's error table. Return the
   updated row through the same `withDerivedStatus` wrapper `findOneFromDb` uses, so the mutation's
   `status` is the derived title status and not the raw column.
9. **`movies(isShort:)`.** `MoviesService.findAll(userId, isShort?: boolean)` adds
   `...(isShort === undefined ? {} : { isShort })` to its `where`. Resolver argument is
   `@Args('isShort', { type: () => Boolean, nullable: true })`; `null` and omitted both mean "no
   filter". Do not add a second query and do not filter in the resolver.
10. **`isShort` on search results.** Add the non-null field to
    `media-search-result.entity.ts`; add `isShort: true` to `enrichWithOwnership`'s `select` and map
    it onto each row (`false` when no registered row exists). In `ShowsService`'s enrichment, set
    `isShort: false` on every row — a series is never a short, and the field is non-null.
    **Do not add `isShort` to `src/clients/types.ts`'s `MediaSearchResult`**: that is the shape
    written to the shared Redis key, and the cache write happens before enrichment
    (`../plan.md` § Contract Freeze).
11. **`Movie.isShort`.** Add the non-null field to `movies/entities/movies.entity.ts`. It comes
    straight off the Prisma row; no `@ResolveField`.
12. **Output root.** In `ProcessJobsService.getEncodeJobDetails`'s film arm, choose
    `path_shorts` when `movie.isShort && await capabilities.isShortsEnabled()`, else `path_movies`;
    widen `resolveOutputRoot`'s parameter union with `'path_shorts'`. Import
    `MediaCapabilitiesModule` in `ProcessJobsModule`. The episode arm is untouched. **Add no lock and
    no snapshot of the flag** — a job whose details were already handed out keeps the root it was
    given, and that is the stated behaviour (spec REQ-13), not a gap to close here.

## Contract obligations

`api` must expose exactly the SDL in `../spec.md` § GraphQL Contract Delta, and exactly these five
refusals, each through `i18nError` so `extensions.i18n.key` reaches `web`:

- `error.media.shorts_disabled` (403) — `addMedia(asShort: true)` or `setMovieShort` while
  `movies_enabled && shorts_enabled` is not true.
- `error.media.shorts_not_a_movie` (400) — `addMedia(asShort: true, type: "show")`, thrown by the
  resolver before any per-type service runs.
- `error.media.type_disabled` (403, existing) — `setMovieShort` / `movies(isShort:)` while movies are
  disabled. Thrown before the shorts guard, so the message names the right cause.
- `error.movie.not_found` (404, existing) — `setMovieShort` for a film the caller does not own,
  indistinguishable from one that does not exist.
- `error.setting.missing` (404, existing) — `getEncodeJobDetails` for a short while `path_shorts` is
  absent from Settings.

`schema.gql` is regenerated on boot, never hand-edited (Constitution, Article IV): it may appear in
the diff as a regeneration artifact, and every field in it must trace to a decorator change in this
slice. The delta is read-only — if it is wrong, stop and report.

## Tests

Owed under Article IX — each of these fails **silently**:

- `src/process-jobs/process-jobs.service.spec.ts` — a wrong `outputRoot` transcodes successfully and
  files the film where the user will not find it; every status still reads `COMPLETED`. Cover all
  four combinations (`isShort` true/false × shorts enabled/disabled) plus `path_shorts` absent →
  `error.setting.missing`. The existing suite already mocks `settings.getMap`, so this is new cases
  in the existing file, not a new file.
- `src/media/media-capabilities.service.spec.ts` — the inverted default. An absent `shorts_enabled`
  row reading as enabled turns a category on for everyone with no error anywhere, and the
  surrounding `!== 'false'` idiom invites exactly that mistake. Also cover
  `movies_enabled: false, shorts_enabled: true` → `shortsEnabled: false`, and that
  `assertShortsEnabled` throws with the right key.
- `src/movies/movies.service.spec.ts` — two things: that `isShort` is **absent** from the object
  handed to `cacheMovies` (a leak into the shared 24h Redis key is invisible to the leaking user and
  wrong for every other one — the suite already asserts this ordering for `mediaId`/`inLibrary`), and
  that `findAll`'s `where` carries the filter only when the argument is given.
- `src/media/media.resolver.spec.ts` — the guard order in `addMedia`, and that no service method is
  called when a guard throws. A guard that runs after registration refuses nothing.

**Not owed:** `setMovieShort`'s ownership refusal beyond one case — it delegates to the already-tested
`findOneFromDb`; the entity/field additions, which are declarations; the Settings catalog entries,
covered by `settings.service`'s existing per-kind validation tests. `shows.service.spec.ts` gets one
assertion that every enriched row carries `isShort: false`, because a missing non-null field is a
runtime error on a screen no `api` test renders.

## Done when

```bash
bin/cli api npx --no tsc --noEmit
bin/npm api test
bin/cli api npx prisma migrate status
```

`tsc` reports 0 errors, the suite passes with the new cases green, and `migrate status` reports the
new migration applied with no drift. `git status services/api/prisma/` shows a modified
`schema.prisma` **and** a new migration directory — one without the other is an Article III
violation.
