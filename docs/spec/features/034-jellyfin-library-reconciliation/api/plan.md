# PLAN: Reconcile a newly registered title against the media server — `api` (`api/plan.md`)

## Scope

This slice owns everything except the Settings UI: the Prisma migration and seeds, the
`MediaServerClient` interface change and Jellyfin's implementation of it, the index module, the
reconcile service, the two trigger points inside `MoviesService`/`ShowsService`, the settings-change
trigger, and the whole GraphQL delta.

It does **not** render anything. `web` owns the Media Server panel, the Re-sync button and both
message catalogs. Writes are confined to `services/api/` and this directory; anything else is a
stop-and-report.

## Existing code to reuse

- `src/shows/shows.service.ts` → `hydrate()`. **The** template for `rebuild()`: Redis
  `SET … NX` claim keyed per job, whole body in `try/catch/finally`, `finally` deletes the claim on
  every exit path, TTL as the backstop for the process dying, and the "synced" marker written only
  after the work is complete. Copy the structure, not the code.
- `src/settings/settings.resolver.ts` → the `changedDownloadsPath` block at the end of
  `updateSettings`. Same position, same reasoning (the resolver fires side effects so the service
  does not grow a cycle). The new trigger goes immediately after it.
- `src/media-server/media-server.service.ts` → `notifyCreated()`. Its exact failure posture: whole
  body in `try/catch`, `console.warn` for "configured but unusable", `console.error` for a real
  failure, and never rethrow. NFR-1 is the same rule for reconciliation.
- `src/ffprobe-logs/ffprobe-logs.resolver.ts` → `@UseGuards(AdminGuard)` **per method**. Do not lift
  it to class level.
- `src/i18n/i18n-error.ts` → `i18nError.badRequest(ERROR_KEYS.MEDIA_SERVER_NOT_CONFIGURED)`.
- `src/types/media.ts` → `MEDIA_TYPE` / `MediaType`. The `mediaType` column stores these two literals.
- `src/clients/media-server/registry.ts` → `MEDIA_SERVERS` stays one line per server; `MEDIA_SERVER_NONE`
  stays the "absence of a client" sentinel that returns `null` rather than throwing.
- `prisma/seeds/settings.ts` → create-only seeding (`findUnique` before `create`).

## Steps

1. **Schema + migration.** Add `MediaServerItem` to `prisma/schema.prisma` per `../spec.md`
   § Data Model Changes. Run `bin/npm api run prisma:migrate`. Both the modified `schema.prisma` and
   the new migration directory must appear in `git status` (Article III).
2. **Seeds.** Add the three index-state rows to `prisma/seeds/settings.ts`. Do **not** touch
   `settings.catalog.ts` — they must stay non-editable.
3. **Error key.** `MEDIA_SERVER_NOT_CONFIGURED: 'error.mediaServer.not_configured'` in
   `error-keys.ts`, beside the existing `MEDIA_SERVER_UNKNOWN`; its English string in `messages.en.ts`.
4. **Client interface.** In `clients/media-server/types.ts`:

   ```ts
   export type MediaServerLibraryEntry = { mediaType: MediaType; tmdbId: number; externalId: string };
   export type MediaServerEpisodeRef = { seasonNumber: number; episodeNumber: number };
   export type MediaServerIndexPort = { lookup(mediaType: MediaType, tmdbId: number): Promise<string | null> };

   export type MediaServerClient = {
     refreshLibrary(): Promise<void>;
     createdMedia(media: string): Promise<void>;
     findByTmdbId(mediaType: MediaType, tmdbId: number): Promise<string | null>;
     listPresentEpisodes(externalSeriesId: string): Promise<MediaServerEpisodeRef[]>;
     listLibrary?(): Promise<MediaServerLibraryEntry[]>;
   };

   export type MediaServerFactory = (config: MediaServerConfig, index: MediaServerIndexPort) => MediaServerClient;
   ```

   `listLibrary` is optional **on purpose** — REQ-8. A client that resolves natively omits it and
   `rebuild()` becomes a no-op for it. Update `createMediaServerClient` in `registry.ts` to take and
   forward the port. `MEDIA_SERVER_OPTIONS` / `MEDIA_SERVER_IDS` do not change.
5. **Jellyfin implementation** in `clients/media-server/jellyfin.ts`, all reads with a 5s timeout
   (`AbortSignal.timeout`), except `listLibrary`, which gets 5 minutes (NFR-2):
   - `findByTmdbId` → `index.lookup(...)`. Jellyfin has no provider-id filter, so this is the whole
     implementation; the comment above it should say so and link
     `https://github.com/jellyfin/jellyfin/issues/16192` (Article XI's external-documentation exception).
   - `listLibrary` → two paged enumerations, `includeItemTypes=Movie` and `includeItemTypes=Series`,
     both with `recursive=true&hasTmdbId=true&fields=ProviderIds&excludeLocationTypes=Virtual&enableImages=false&enableUserData=false`,
     paging on `startIndex`/`limit` at 500. Keep an entry only when `ProviderIds.Tmdb` parses to a
     positive integer (REQ-12). `userId` is not sent — it is optional for API-key auth
     (`ItemsController.cs:82`).
   - `listPresentEpisodes` → `GET /Shows/{externalSeriesId}/Episodes?isMissing=false&fields=`, then
     **also** drop any item whose `LocationType === 'Virtual'` or whose `Path` is empty, and any item
     missing `ParentIndexNumber` or `IndexNumber`. The double filter is deliberate: see the risk table
     in `../plan.md`. Map to `{ seasonNumber: ParentIndexNumber, episodeNumber: IndexNumber }`.
   Keep the pure mappers as exported functions so the spec file can drive them without HTTP.
6. **`media-server-index/`.** New module importing only `PrismaModule` and `RedisModule`.
   `MediaServerIndexService`:
   - `lookup(mediaType, tmdbId)` → `findUnique` on the composite key, returns `externalId` or `null`.
   - `rebuild(clientId, config)` → claims `mediaserver:index:rebuild` via `SET … NX` (returns the
     current state if not claimed — REQ-7); builds the client via the registry; returns early when the
     client has no `listLibrary`; enumerates; then **one** `$transaction([deleteMany, ...createMany
     chunks])` with an **explicit `timeout`** (the 5s default will not survive a real library — see
     `../plan.md` risks) and `createMany` chunked at 1000. Writes the state rows on success; on failure
     writes `failed` and leaves both the table and `media_server_index_synced_at` untouched (REQ-4,
     REQ-5). `try/catch/finally`, claim released in `finally`.
   - `readState()` → **derives** `state`: `syncing` only while the Redis claim is actually held;
     a stored `syncing` with no live claim reports `failed`. Reads the three `Setting` rows via
     `prisma.setting` directly — they are not catalog settings and must not go through
     `SettingsService`, which would reintroduce the cycle this module exists to avoid.
7. **`MediaServerReconcileService`** in `media-server/`, importing `MediaServerIndexModule` and
   `SettingsModule`. A private `client()` helper resolves settings → client, returning `null` for
   `none` / empty host (REQ-20), mirroring `notifyCreated`'s early returns. Then:
   - `reconcileMovie(movieId, tmdbId)` → `findByTmdbId(MEDIA_TYPE.MOVIE, tmdbId)`; on a hit,
     `prisma.movie.updateMany({ where: { id: movieId, status: 'MISSING' }, data: { status: 'COMPLETED' } })`.
     Never writes `filePath`, never writes `MISSING`.
   - `reconcileShow(showId, tmdbId)` → `findByTmdbId(MEDIA_TYPE.SHOW, tmdbId)`; on a hit,
     `listPresentEpisodes(externalId)`, then resolve each `(seasonNumber, episodeNumber)` against the
     show's own seasons/episodes and promote with the same `status: 'MISSING'` guard. Season 0 is not
     filtered (REQ-13). An episode number the show does not have is skipped silently.
   - Both wrapped so nothing ever escapes (NFR-1).
8. **Trigger points.**
   - `MoviesService.register()` — `await` the reconcile before returning, on **both** branches
     (existing row and new row). It costs one indexed DB read, no HTTP (NFR-3), so awaiting is right.
   - `ShowsService.hydrate()` — call `reconcileShow` at the very tail, **after** the
     `show.update({ seasonsSyncedAt })` write, so a reconcile failure cannot make the next
     `register()` re-fetch the whole catalog (REQ-19).
   - `ShowsService.register()`, **existing-show branch** — call `reconcileShow` directly, detached.
     Without this, re-adding an already-hydrated series skips reconciliation entirely and REQ-18's
     documented retry silently does nothing. This is the easiest step in the plan to miss.
9. **Resolver.** In `media-server.resolver.ts`, add `mediaServerIndexStatus` and
   `resyncMediaServerIndex`, each with its own `@UseGuards(AdminGuard)`. The existing
   `mediaServerClients` query stays unguarded — do not lift the guard to class level.
   `resyncMediaServerIndex` reads the config off `SettingsService`, throws
   `MEDIA_SERVER_NOT_CONFIGURED` for `none`/empty host, starts `rebuild()` **detached** (`void`, never
   awaited — NFR-6) and returns `readState()` immediately.
10. **Settings trigger.** In `SettingsResolver.updateSettings`, capture `getMap()` **before**
    `updateMany`, then after the write compare the four media-server keys, considering **only keys
    present in `entries`** and only when the submitted value differs from the stored one. If any
    differ, fire the same detached `rebuild()`. Place it immediately after the existing
    `changedDownloadsPath` block. `SettingsModule` imports `MediaServerIndexModule` (the leaf — never
    `MediaServerModule`, which would be circular).
11. **Wiring.** `MediaServerModule` imports `MediaServerIndexModule` and exports
    `MediaServerReconcileService`; `MoviesModule` and `ShowsModule` import `MediaServerModule`.
    Confirm no cycle: nothing under `media-server*/` imports `movies/` or `shows/`.

## Contract obligations

Exposed exactly as `../spec.md` § GraphQL Contract Delta freezes it:

```graphql
type MediaServerIndexStatus { state: String!  itemCount: Int!  syncedAt: DateTime }
type Query    { mediaServerIndexStatus: MediaServerIndexStatus! }
type Mutation { resyncMediaServerIndex: MediaServerIndexStatus! }
```

`state` is `String!` — **not** a `registerEnumType`. `syncedAt` is nullable; `itemCount` is non-null
and is `0` before the first successful rebuild. `resyncMediaServerIndex` never waits for the rebuild.
`addMedia`, `Movie`, `Show` and `Episode` are unchanged; `schema.gql` must show no other diff.

Errors: `error.mediaServer.not_configured` (`BadRequestException`) and the existing
`error.auth.admin_required` and `error.mediaServer.unknown`. No other new key.

The delta is read-only. If it is wrong, stop and report — do not adapt it locally.

## Tests

Three files are owed one under Article IX. Each opens with a paragraph naming the failure it
defends against; write the cases fault-injection style (verify each fails when its rule is removed),
following `media-roots.service.spec.ts` and `magnet.spec.ts`.

- `src/clients/media-server/jellyfin.spec.ts` — **the mappers**. A wrong field name (`ProviderIds.Tmdb`,
  `ParentIndexNumber`, `IndexNumber`, `LocationType`) yields an empty list, not an error: the index
  builds "successfully" with zero entries and every title reads `MISSING`, which is also the correct
  output for an empty library. Cases: an item with no `Tmdb` provider id is dropped; a non-numeric or
  zero `Tmdb` is dropped; a `LocationType: "Virtual"` episode is dropped **even though the request
  asked for `isMissing=false`**; an episode with a null `IndexNumber` is dropped; a well-formed film
  and series map to the right `mediaType`.
- `src/media-server-index/media-server-index.service.spec.ts` — **the composite key and the failed
  rebuild**. Cases: a film and a series with the same `tmdbId` coexist and `lookup` returns each one's
  own `externalId` (drop `mediaType` from the key and this must fail); a rebuild whose enumeration
  throws leaves both the previous rows and `media_server_index_synced_at` untouched; a second
  concurrent `rebuild()` does not start while the claim is held; a stored `syncing` with no live claim
  reads back as `failed`.
- `src/media-server/media-server-reconcile.service.spec.ts` — **the never-downgrade guard**. Cases: a
  `DOWNLOADING` film that the server holds stays `DOWNLOADING`; likewise `ENCODING` and `ERROR`; a
  `MISSING` film becomes `COMPLETED` with `filePath` still null; an episode present in the server but
  absent from the show is skipped without throwing; season 0 is reconciled like any other; nothing is
  ever written as `MISSING`; a client throwing does not propagate out of `reconcileMovie`.

**Not owed a test**: the resolver's guard placement (the `ffprobe-logs.resolver.spec.ts` precedent
exists because a misplaced guard there silences the worker; here a misplaced guard fails loudly on the
first admin call), the seeds (create-only, and a missing row surfaces as `state: never`), and the
settings-change comparison (a wrong result is a spurious or missing rebuild, both visible on screen
via REQ-6).
