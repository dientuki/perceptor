# PLAN: User Preferences — `api` (`api/plan.md`)

Read `../spec.md` and `../plan.md` first, then `services/api/CLAUDE.md` and
`docs/constitution.md`. The GraphQL delta in `../spec.md` is read-only.

## Scope

`api` owns everything behind the screen: the migration, the two new enums, the three new tables,
the column on `users`, one new Nest module exposing `Query.preferences`, `Query.torrentGroups` and
the three mutations, and one new method on each of `LanguagesService` and `UsersService`.

`api` does **not** build any UI, and does **not** consume any of the values it stores. In
particular: `ProcessJobsService`'s language merge, `resolveDefaultLanguages`, the
`ProcessJobDetails` payload and every `Setting` — including `default_languages` and its
`SETTINGS_CATALOG` entry — are untouched (REQ-6, NFR-1, NFR-3). A diff of this slice that reaches
`src/process-jobs/` or `src/settings/` is out of scope and is a stop-and-report.

Writes are confined to `services/api/` and this directory. Anything else is a stop-and-report (see
`.claude/agents/api.md`).

## Existing code to reuse

- **`src/languages/languages.service.ts`** is the template for the entire write path, and
  `validateAndResolveLanguageIds` is reused *as it is*, not copied: it already rejects a duplicated
  tag (`error.language.duplicate`) and an unknown one (`error.language.unavailable`) before any
  write, and `SettingsService` already reuses it for the same reason. `setMoviePreferredLanguagesFor`
  (`:86`) is the exact shape `setPreferredTrackLanguagesFor` takes — resolve, then `$transaction`,
  then re-read — with `{ userId, movieId }` becoming `{ userId, kind }` in the `deleteMany`. That
  `kind` in the `where` is the whole risk surface of this slice; see § Tests.

- **`src/users/users.service.ts:207` (`setUiLocale`)** is the precedent for a self-service write
  against the `users` table: a narrow method taking a user id and a value, doing one
  `prisma.user.update`, returning the row. `setAllowCinemaReleases` is its twin. Do not route this
  through `UsersService.update` — that is the administrator CRUD path with its own validation and
  its own error keys.

- **`src/auth/auth.resolver.ts`** is the reference for a resolver rooted at the caller: `@CurrentUser()
  principal`, an explicit `principal.type !== 'user'` narrowing that throws
  `ERROR_KEYS.AUTH_UNAUTHENTICATED`, `@UseGuards(JwtAuthGuard)`, and no `@AllowService()`. Every
  operation in `PreferencesResolver` follows it. Note that the global guard already refuses an
  anonymous caller — the narrowing is what refuses a `SERVICE_TOKEN` principal and what gives
  TypeScript `.id` (AC-12).

- **`src/i18n/i18n-error.ts` + `src/i18n/error-keys.ts` + `src/i18n/messages.en.ts`** — every throw
  goes through `i18nError.badRequest(ERROR_KEYS.X, params)`. Never `new BadRequestException('…')`,
  and never a Spanish string: this service produces English `message` plus a key, and `web`
  translates (`services/api/CLAUDE.md` § "Errors carry a translation key").

- **`src/languages/entities/language.entity.ts`** — the `@ObjectType()` shape the new entities
  follow. `Language` itself is reused unchanged as the return type of `setPreferredTrackLanguages`
  and as the element type of the two list fields on `UserPreferences`.

- **`src/media-sources/`'s `registerEnumType` usage** — the existing pattern for exposing a Prisma
  enum to GraphQL. Verify with `grep -rn "registerEnumType" src/` and follow what is there rather
  than inventing a placement.

- **`prisma/schema.prisma`'s `UserMovie`/`UserMovieLanguage` pair** — the shape of a
  user-scoped join table: composite `@@id`, `onDelete: Cascade` on both relations, `@@index` on the
  non-leading key, `@@map` to a snake_case table name. REQ-12 is satisfied by that `Cascade` and by
  nothing else — no cleanup code in `UsersService.remove`.

**Article XI applies to every new file.** The files named above are full of explanatory comments;
all of them predate the article and are legacy. Copy their ordering and their structure, and write
no comment — the single exception in this slice is the header paragraph each new `*.spec.ts` owes
under Article IX.

## Steps

1. Add to `prisma/schema.prisma`: enums `LanguageTrackKind { AUDIO SUBTITLE }` and
   `TorrentGroupScope { MOVIE SHOW }`; `allowCinemaReleases Boolean @default(false)` plus the
   `languages`/`torrentGroups` back-relations on `User`; `userPreferences` on `Language`; and the
   three models exactly as `../spec.md` § Data Model Changes tables them. Generate the migration
   with `bin/npm api run prisma:migrate` and confirm `git status services/api/prisma/` shows both a
   modified schema and a new migration directory.

2. Add the three `error.torrent_group.*` keys to `src/i18n/error-keys.ts` and their English
   templates to `src/i18n/messages.en.ts`, with the exact strings from `../spec.md` § Error table
   and the exact `{param}` names.

3. Add `src/preferences/entities/` — the two enums via `registerEnumType`, `TorrentGroup`, and
   `UserPreferences` with its four fields.

4. Add `setPreferredTrackLanguagesFor(userId, kind, tags)` and
   `findPreferredTrackLanguagesFor(userId, kind)` to `LanguagesService`, beside the two per-title
   pairs. `validateAndResolveLanguageIds` first, then a `$transaction` whose `deleteMany` is keyed
   on `{ userId, kind }` — **not** `{ userId }` — then `createMany`, then re-read through the
   finder.

5. Add `setAllowCinemaReleases(userId, allowed)` to `UsersService`.

6. Write `PreferencesService`: `findForUser(userId)` returning the four values in one shape;
   `setAllowCinemaReleases` delegating to `UsersService` and re-reading; `findCatalog(scope?)` for
   `Query.torrentGroups`; and `setPreferredTorrentGroupsFor(userId, scope, ids)` — the only write it
   owns. That last one resolves the ids against `torrent_groups` **before** any write and throws
   `TORRENT_GROUP_DUPLICATED` on a repeated id, `TORRENT_GROUP_NOT_FOUND` on an id with no row and
   `TORRENT_GROUP_WRONG_SCOPE` on a row whose `scope` differs from the argument — then replaces
   inside a `$transaction` with the `deleteMany` keyed on the user **and** the scope (a join to
   `torrent_groups`, since `user_torrent_groups` carries no scope column of its own).

7. Write `PreferencesResolver` — `preferences`, `torrentGroups(scope)`, `setAllowCinemaReleases`,
   `setPreferredTrackLanguages`, `setPreferredTorrentGroups` — every one guarded and narrowed as
   `AuthResolver` does, none carrying `@AllowService()`, none taking a user id.

8. Write `preferences.module.ts` importing `LanguagesModule` and `UsersModule` (both already export
   their service), and register it in `src/app.module.ts`.

9. Write `preferences.service.spec.ts` and extend `languages.service.spec.ts` (§ Tests).

10. Boot the service and diff the regenerated `src/schema.gql` against `../spec.md` § Schema. Any
    difference is either a contract violation or a stale spec, and both stop the slice
    (Article VIII's Check).

## Contract obligations

`api` produces exactly the surface in `../spec.md` § GraphQL Contract Delta — nothing more and
nothing renamed. `web` retypes it by hand with no codegen, so a field named differently here is a
runtime failure over there with no compile error anywhere.

Specifically owed:

- `Query.preferences: UserPreferences!` and `Query.torrentGroups(scope: TorrentGroupScope): [TorrentGroup!]!`
  — the second with `scope` **optional**, returning the whole catalog when omitted.
- `UserPreferences.torrentGroups` unfiltered, both scopes in one list.
- `setPreferredTrackLanguages(kind:, tags:)` returning `[Language!]!` — the resulting list for that
  kind only.
- `setPreferredTorrentGroups(scope:, ids:)` returning `[TorrentGroup!]!` — the resulting selection,
  which per the contract is the whole selection for that scope, and which must leave the other
  scope's rows untouched.
- `setAllowCinemaReleases(allowed:)` returning the whole `UserPreferences`.
- Every failure in the error table, thrown through `i18nError` with the listed key and params.

Nothing is added to the `User` type. If exposing this from `me` looks obviously better from inside
this slice, read `../plan.md` § Contract Freeze before acting on it — that shape was deliberately
deleted by `029-settings-screen-tabs` and its removal is why the guard it needed is gone.

## Tests

Two files, and both are owed for the same reason: a scope-blind or kind-blind delete produces
**no error anywhere**. The write succeeds, the mutation returns the correct list for what was
written, and the other list is simply gone. Nothing in the type system, the schema or the logs
notices.

- **`src/preferences/preferences.service.spec.ts`** — the new suite. Cases:
  1. Saving `MOVIE` groups leaves the caller's `SHOW` rows in place, and the reverse.
  2. Saving `MOVIE` groups leaves *another user's* rows in place — the `deleteMany` must be keyed on
     the user as well as the scope.
  3. An id whose row is `SHOW`, passed with `scope: MOVIE`, throws `error.torrent_group.wrong_scope`
     and writes nothing.
  4. An id matching no row throws `error.torrent_group.not_found` and writes nothing.
  5. A repeated id throws `error.torrent_group.duplicated` and writes nothing.
  6. `ids: []` clears that scope and only that scope.

  Cases 3–5 must assert **both** the throw and that the stored set is unchanged; a test that only
  asserts the throw passes against an implementation that validates halfway through the write.

- **`src/languages/languages.service.spec.ts`** — one case added to the existing suite: saving
  `AUDIO` leaves the caller's `SUBTITLE` rows in place, and the reverse.

Both must be written by **fault injection**, the house technique named in `services/api/CLAUDE.md` §
Tests: widen the `deleteMany`'s `where` to `{ userId }`, confirm the case fails, restore it. A case
that passes with and without the bug is not a test of it. Each file opens with the one-paragraph
header Article IX requires.

**Not owed:**

- `setAllowCinemaReleases` — a boolean write with no branch, whose failure is visible immediately on
  the screen and in `select allowCinemaReleases from users`.
- `Query.torrentGroups` / `findForUser` — plain reads with no filtering logic beyond an optional
  `where`. A bug there renders an empty or wrong picker, which is loud.
- The resolver guards — the `principal.type !== 'user'` narrowing is one line copied from
  `AuthResolver` and is covered end to end by AC-12.
