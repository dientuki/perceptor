# PLAN: Film Grain Optimization — `api` (`api/plan.md`)

## Scope

This service owns everything stored and everything resolved: the Prisma enum and the two columns,
the `grain_auto_enabled` Settings catalog entry and its seed, the two `GrainMode` GraphQL enums,
the two `set*GrainMode` mutations, and the two-level resolution that turns a title's override plus
the installation switch into the single `EffectiveGrainMode` the worker consumes.

It does **not** decide what `AUTO` means. `api` emits `AUTO` and stops there; the worker resolves it
(`../worker/plan.md`). It also writes no UI copy — `web` owns every user-facing string.

Writes are confined to `services/api/` and this directory. Anything else is a stop-and-report.

## Existing code to reuse

- `src/media/entities/content-kind.enum.ts` — the exact file shape for a GraphQL enum that is also
  a Prisma enum: a TS `enum` with string values plus `registerEnumType`. Copy it; both new enums
  live in one new file beside it.
- `src/settings/subtitle-formats.ts`'s `resolveAllowedSubtitleFormats` — the precedent for a pure
  resolver fed `SettingsService.getMap()`'s output and called once from `getEncodeJobDetails`. The
  new `grain-mode.ts` is its sibling in the same directory and must not grow a Nest module.
- `MediaCapabilitiesService.assertEnabled(MEDIA_TYPE.MOVIE | SHOW)` — the type gate, called
  **before** the ownership read in both resolvers. `setMovieContentKind`'s comment explains why;
  copy that ordering, not a new one.
- `MoviesService.findOneFromDb(id, userId)` + `i18nError.notFound(ERROR_KEYS.MOVIE_NOT_FOUND, { id })`
  — the film's ownership gate, which lives in the **service** (`setContentKind`'s shape).
- `ShowsResolver`'s own `findOneFromDb` + `ERROR_KEYS.SHOW_NOT_AVAILABLE` check — the series'
  ownership gate, which lives in the **resolver**. This asymmetry is deliberate and pre-existing
  (`057` kept it rather than unifying); do not fix it here.
- `MoviesService.withDerivedStatus(updated)` and `ShowsService.deriveSeasonEpisodeStatuses(...)` —
  the return shapes `setContentKind` already produces for `Movie!` and `Show!`.
- `ProcessJobsService.getEncodeJobDetails`'s `base` object and its `settingsMap` — `compressionEnabled`
  and `compressionResolution` are resolved there off one `getMap()` call. `grainMode` rides the same
  call (NFR-1) and goes in the same object, since both the film and episode arms spread `base`.
- The `movie.contentKind as unknown as ContentKind` cast in `getEncodeJobDetails` — the documented
  bridge between Prisma's string-literal union and the nominal TS enum `registerEnumType` needs.
  The same cast applies to `grainMode`, in both directions (resolver argument in, field out).
- `settings.catalog.ts`'s `compression_enabled: { kind: 'boolean' }` — the catalog entry, which is
  all that is needed for `updateSettings` to validate and persist the new row.

## Steps

1. `schema.prisma`: add `enum GrainMode`, add `grainMode GrainMode @default(INHERIT)` to `Movie`
   and `Show`. Generate the migration with `bin/npm api run prisma:migrate`. No backfill.
2. `prisma/seeds/settings.ts`: append `grain_auto_enabled` with `'false'`. Note this file runs under
   plain ts-node with no `@/*` alias — the literal stays a literal, as `compression_resolution`'s
   `'1080p'` does.
3. New `src/media/entities/grain-mode.enum.ts`: `export enum GrainMode { INHERIT, ON, OFF }` and
   `export enum EffectiveGrainMode { AUTO, ON, OFF }`, each `registerEnumType`d with the names the
   contract freezes.
4. `settings.catalog.ts`: `grain_auto_enabled: { kind: 'boolean' }`.
5. New `src/settings/grain-mode.ts`:
   `resolveEffectiveGrainMode(titleGrainMode: 'INHERIT' | 'ON' | 'OFF', settingsMap: Record<string, string>): EffectiveGrainMode`.
   `ON` → `ON`; `OFF` → `OFF`; `INHERIT` → `AUTO` when `settingsMap['grain_auto_enabled'] === 'true'`,
   else `OFF`. **`=== 'true'`, never `!== 'false'`** (REQ-2) — an absent row reads as off, the
   `shorts_enabled` idiom, the deliberate opposite of `compression_enabled`'s.
6. Add `grainMode` to `movies.entity.ts` and `show.entity.ts` as `@Field(() => GrainMode)`.
7. `MoviesService.setGrainMode(id, userId, grainMode)` — a clone of `setContentKind`: ownership
   gate, single-column `update`, `withDerivedStatus`.
8. `MoviesResolver.setMovieGrainMode(movieId, grainMode)` — `assertEnabled(MOVIE)` first, then
   delegate. No shorts-style second capability check: grain has no installation on/off switch that
   gates the *control* (the setting is a default, not a capability).
9. `ShowsService.setGrainMode(id, grainMode)` + `ShowsResolver.setShowGrainMode(showId, grainMode)`
   — the series twins, with the ownership gate in the resolver per the asymmetry above.
10. `encode-job-details.entity.ts`: `@Field(() => EffectiveGrainMode) grainMode: EffectiveGrainMode`.
11. `getEncodeJobDetails`: call `resolveEffectiveGrainMode` on `base`. The film arm passes
    `movie.grainMode`; **the episode arm passes `show.grainMode`** — the series is already loaded
    via `episode.season.show` for `contentKind`, so this costs no query.
12. Add the spec locators (`// Spec 092, REQ-n`) on the non-obvious lines — the `=== 'true'`
    operator, the episode arm's series read — and nothing else (Article XI).

## Contract obligations

From `../spec.md` § GraphQL Contract Delta, read-only:

- `Movie.grainMode: GrainMode!`, `Show.grainMode: GrainMode!` — non-null, default `INHERIT`.
- `EncodeJobDetails.grainMode: EffectiveGrainMode!` — non-null, **never `INHERIT`**. This is the
  single obligation the worker's correctness rests on: emitting `INHERIT` here would be normalized
  to `OFF` by the worker with one log line and no error, and a series set to `ON` would quietly
  encode grain-free forever.
- `setMovieGrainMode(movieId: Int!, grainMode: GrainMode!): Movie!` and
  `setShowGrainMode(showId: Int!, grainMode: GrainMode!): Show!`.
- Errors, all four already in `error-keys.ts`, none new: `error.movie.not_found` (film, not owned or
  absent), `error.show.not_available` (series, same), `error.media.type_disabled` (the type's switch
  is off — thrown **before** the ownership read), `error.setting.expected_boolean` (a
  `grain_auto_enabled` write that is not `"true"`/`"false"`, produced by the existing catalog
  validation with no new code).
- No new Settings query surface: `grain_auto_enabled` travels through the existing
  `settings`/`updateSettings` pair.

## Tests

- `src/settings/grain-mode.spec.ts` — **owed**. The precedence rule is the whole feature and every
  way of getting it wrong is silent: a title on `OFF` that still reads the setting, an `INHERIT`
  that defaults to `AUTO` instead of `OFF`, or the `!== 'false'` operator slipping in, all produce a
  perfectly successful encode with the wrong parameters and no error in any log. Follow the house
  fault-injection technique: each case must be verified to fail when the rule it covers is removed.
  Cover all three title values × the setting present/absent/`'maybe'`.
- `src/process-jobs/process-jobs.service.spec.ts` — **owed**, two cases beside the existing
  `compression_resolution` ones: a film job carries its own film's resolved value, and an **episode**
  job carries its **series'**. The second is the one that matters — reading an episode-level value
  that does not exist would fall back to a default silently.
- `src/movies/movies.resolver.spec.ts` — **owed**, one case: `assertEnabled` is called before the
  ownership read. `057` added the same case for `setMovieContentKind`; the failure (an id's
  existence leaking to a caller whose type is disabled) produces no error anywhere.
- `src/shows/shows.service.ts`'s `setGrainMode`, the two entity fields, the catalog entry and the
  seed row — **not owed**. A wrong column name, a missing `@Field` or an unseeded row fails loudly
  at boot, at schema generation, or in the typecheck.
