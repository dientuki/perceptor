# PLAN: AV1 Transcode — `api` (`api/plan.md`)

## Scope

This slice owns everything behind the contract: the migration that creates the three preference
tables, the `languages` query the pickers read, the three mutations that write a preference, the two
field resolvers that read one back, and the merge that turns all of it into
`allowedLanguagesIso3` on the encode payload.

It does **not** touch the FFmpeg rules — `worker` owns every decision about which stream to keep and
which CRF to use, and reads this slice's output as a plain list of ISO-639-2 codes. It does not
build any UI. It does not add or change a `SETTINGS_CATALOG` key: the global preference is per user,
not per installation, and `settings.catalog.ts` must come out of this feature unmodified.

Writes are confined to `services/api/` and this directory. Anything else is a stop-and-report (see
`.claude/agents/api.md`).

## Existing code to reuse

- **`ProcessJobsService.resolveIso3`** (`src/process-jobs/process-jobs.service.ts`) — already turns
  a TMDB `iso2` into the `iso3` the worker needs, via `prisma.language.findUnique`. Keep it exactly
  as it is, including the `?? 'eng'` fallback, and use it for the *original* language only. The
  merged extras come back as `iso3` straight from the join and need no second lookup.
- **`MoviesService.findOneFromDb(id, userId)`** (`src/movies/movies.service.ts`) — the ownership
  `findFirst` with `where: { id, users: { some: { userId } } }`. `setMoviePreferredLanguages` must
  call it before writing, and throw the identical `La película <id> no existe` on `null`. Do not
  write a second ownership check.
- **`ShowsService.findOneFromDb(id, userId)`** (`src/shows/shows.service.ts`) — the same, one level
  up, for `setShowPreferredLanguages`; refusal message `Recurso no disponible para este usuario`.
- **`@CurrentUser()` + the principal union** (`src/auth/decorators/current-user.decorator.ts`,
  `src/auth/auth.types.ts`) — every mutation here needs the narrowing
  `principal.type === 'user' ? principal.id : ''` that `MoviesResolver` and `ShowsResolver` already
  do. Copy it; do not invent a helper.
- **`MediaServerRegistry`'s shape** (`src/clients/media-server/registry.ts`) — the precedent for
  "options come from one place, never a hard-coded list at the call site". `languages` plays that
  role here for the web pickers.
- **The `movies`/`shows` resolver pair** — `MoviesResolver` and `ShowsResolver` are deliberate
  structural twins (`006-media-search`, `009-show-detail`). The two new mutations and two new field
  resolvers must keep that symmetry; do **not** factor them into a shared base class, for the same
  reason recorded in `006-media-search/spec.md` § Out of Scope.
- **`prisma/seeds/languages.ts`** — the 20 seeded rows. Nothing in this slice re-seeds or extends
  them; `languages` reads whatever is there.

## Steps

1. **Schema.** Add the three models to `prisma/schema.prisma` with composite primary keys and
   `onDelete: Cascade` on every relation. `UserMovieLanguage`/`UserShowLanguage` reference
   `UserMovie`/`UserShow` through the composite foreign key (`userId` + `movieId` /
   `userId` + `showId`), not through `User` and `Movie` separately — the preference must die with
   the ownership. `@@map` to `user_languages`, `user_movie_languages`, `user_show_languages`.
2. **Migration.** `bin/npm api run prisma:migrate`, name it `add_language_preferences`. Confirm
   `git status services/api/prisma/` shows both the modified schema and the new migration directory
   (Article III's check). No backfill.
3. **`languages/` module.** `Language` entity, `language-names.ts` (Spanish names keyed by `iso2`,
   covering all 20 seeded rows), `LanguagesService.findAll()` reading `prisma.language.findMany`
   ordered by name, `LanguagesResolver`'s `languages` query. Register in `app.module.ts` and export
   the module so the other three resolvers can use its service.
4. **Preference writes.** One service method per target, all with the same shape: validate every
   `iso2` against `languages` (`BadRequestException` naming the offending code), reject duplicates
   within one argument, then replace the whole set in a transaction (`deleteMany` + `createMany`).
   Passing `[]` clears. `setPreferredLanguages` takes no user argument — it reads `@CurrentUser()`.
   The two per-title ones call `findOneFromDb` first and propagate its refusal unchanged.
5. **Preference reads.** Three `@ResolveField()`s returning the *calling user's own* list:
   `User.preferredLanguages` on `AuthResolver` (so it rides on `me`), `Movie.preferredLanguages` on
   `MoviesResolver`, `Show.preferredLanguages` on `ShowsResolver`. A field resolver only runs when
   the client selects it, which is what keeps the `movies`/`shows` listings from turning into N+1 —
   do not move any of these into the service's `include`.
6. **The merge.** In `getEncodeJobDetails`, after resolving the movie or episode, build
   `allowedLanguagesIso3`: `resolveIso3(originalLanguage)` first, then the union of every owner's
   global and per-title preference, deduplicated, order otherwise unimportant. For a movie the
   owners are `UserMovie` rows for that `movieId`; for an episode they are `UserShow` rows for
   `episode.season.showId`. Select `language.iso3` from the join — never `iso2`. A title with no
   owners yields just the original, with no special case.
7. **Entity.** Add `allowedLanguagesIso3: [String!]!` to `EncodeJobDetails` with a comment saying
   why `originalLanguageIso3` stays beside it (the worker needs to know which one is mandatory).
8. **Regenerate and check.** Boot the service, then `git diff src/schema.gql` and compare against
   `../spec.md` § GraphQL Contract Delta field by field. Any difference is a stop-and-report.

## Contract obligations

The exact shape this service must expose, from `../spec.md` § GraphQL Contract Delta — read-only:

- `type Language { id: ID! iso2: String! iso3: String! name: String! }`
- `Query.languages: [Language!]!`
- `User.preferredLanguages: [Language!]!` — on `me`, not on the admin `users`/`user(id)` queries
- `Movie.preferredLanguages: [Language!]!`, `Show.preferredLanguages: [Language!]!` — the caller's
  own list, never the merge
- `Mutation.setPreferredLanguages(iso2: [String!]!): [Language!]!`
- `Mutation.setMoviePreferredLanguages(movieId: Int!, iso2: [String!]!): [Language!]!`
- `Mutation.setShowPreferredLanguages(showId: Int!, iso2: [String!]!): [Language!]!`
- `EncodeJobDetails.allowedLanguagesIso3: [String!]!` — always non-empty, original first, ISO-639-2

The five error rows in the spec's table are the complete set of user-facing strings this slice may
introduce. Two of them (`La película <id> no existe`, `Recurso no disponible para este usuario`) are
reused verbatim from `008-movie-detail`/`009-show-detail` — do not reword them.

None of the three mutations gets `@AllowService()`. `processJob(id)` keeps the one it has.

If any of this is wrong, stop and report. Do not adapt it locally (Article VIII).

## Tests

- **`src/process-jobs/process-jobs.service.spec.ts`** (new) — defends against the merge silently
  returning too few languages. A wrong `where` clause here drops a language the user asked for,
  the encode succeeds, and nothing anywhere reports an error; the user finds out while watching.
  Cases: a movie with two owners with different globals and one per-title extra returns the union;
  the original is always present even with zero preferences; the returned codes are `iso3` and not
  `iso2` (assert `'spa'`, verified to fail if the select is switched to `iso2`); an episode resolves
  its owners through `season.show`, not through the episode; a title with no owners returns exactly
  one element. Follow `src/movies/movies.service.spec.ts`'s `findOneFromDb` block for structure —
  each case must be verified to fail when the clause it covers is removed.
- **`src/languages/languages.service.spec.ts`** (new) — defends against a preference write that
  partially applies. Replacement is `deleteMany` + `createMany` in a transaction; if it is not
  atomic, a failed write leaves a user with half their languages and reports success. Cases:
  replacing a set removes the old rows; `[]` clears; an unknown `iso2` throws before anything is
  deleted; a duplicated `iso2` in one argument throws.
- **`src/movies/movies.service.spec.ts` / `src/shows/shows.service.spec.ts`** — extended, not
  replaced, if the ownership guard on the two new mutations lives in those services. Both files are
  real suites already; add cases to them rather than creating a twelfth and thirteenth suite, the
  same call `007-library-listing` and `008-movie-detail` made.
- **Not owed**: `LanguagesResolver` and the three `@ResolveField()`s. They are one-line delegations
  to a tested service, and a mistake there is a GraphQL error the caller sees immediately — a loud
  failure, not a silent one (Article IX).

Every new spec file opens with a comment naming the failure it prevents. Follow
`src/media-roots/media-roots.service.spec.ts` for structure, English `it(...)` strings per
Article VI.
