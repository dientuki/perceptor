# PLAN: Download Status and Torrent Tags — `api` (`api/plan.md`)

Read `../spec.md` and `../plan.md` first. The GraphQL delta and the torrent-client interface delta
in `../spec.md` are **read-only** — if either is wrong, stop and report (Constitution, Article VIII).

## Scope

This slice owns everything except the screen: the Prisma migration that inverts
`Movie` ↔ `MediaSource`, the qBittorrent client methods, the tagging on every acquisition path, the
new `downloads/` read and control surface, the race arbiter in `torrentCompleted`, and the loser
sweep inside `downloadRemove`. It also retires `force` from five mutations and from the two upload
branches that carry the same conflict.

It is **not** building the panel, the refresh control, the confirmation dialog or any Spanish UI
copy beyond exception messages — `web` owns those. It is **not** touching `services/worker`: the
worker's call sites and payloads are unchanged, and `encode.job.ts:146`'s rethrow already makes
cleanup unreachable on a failed encode, which is what REQ-16 asks for. A change that appears to
require editing `services/worker` is a contract error — stop and report.

Writes are confined to `services/api/` and this directory.

## Existing code to reuse

- **`src/clients/torrent/client.ts`** — every new method copies the shape already there:
  `new URL("<name>", await this.baseUrl())`, `HTTP_METHOD` from `@/types/http`, a
  `URLSearchParams` body, `this.normalizeHashes()` for the `|` join, and a JSDoc block whose second
  line is the wiki deep link. POST, like the existing `stop`/`remove`, even where the wiki says GET
  — that is what works against the running container.
- **`add()`'s `response.ok` check and its comment** (`client.ts:128`) — the model for NFR-6. Reuse
  the reasoning and the message shape; the new copy reads `qBittorrent rechazó la operación
  (<status>)`.
- **`MoviesService.findOneFromDb` / `ShowsService.findOneFromDb`** — the ownership clause
  `where: { id, users: { some: { userId } } }`, and the rule that an unowned and a missing row are
  indistinguishable. `DownloadsService` writes the same clause locally rather than importing those
  services; see `../plan.md` § Approach for why, and do not introduce a shared helper.
- **`episodeDisplayTitle` / `seasonDisplayTitle`** — already duplicated in `movies/`, `episodes/`
  and `seasons/`. `Download.label` uses the same rendering (`<Show> S03E08`,
  `<Show> Temporada 3`). Follow the existing duplication; unifying it is a different change.
- **`ProcessJobsService.downloadRemove`** (`process-jobs.service.ts:260`) — the loser sweep goes
  inside it, after the existing `torrentClient.remove` call. Its `!mediaSource.infoHash` early
  return and its `omitido: …` string stay exactly as they are.
- **`DownloadsService.handleTorrentCompleted`'s guard ladder** — REQ-13's new check is one more
  rung, placed **before** the existing `ERROR` rung. Keep the existing style: return a string,
  never throw, log with the `[torrentCompleted]` prefix.
- **`@CurrentUser()`** (`auth/decorators/current-user.decorator.ts`) and the
  `principal.type === 'user' ? principal.id : ''` idiom every resolver already uses.

## Steps

1. **Migration.** Edit `schema.prisma`: add `movieId Int?` + `movie Movie? @relation(...)` to
   `MediaSource` mirroring `episodeId`/`seasonId`; remove `mediaSourceId` and `mediaSource` from
   `Movie`. Run `bin/npm api run prisma:migrate`. Confirm both a modified `schema.prisma` and a new
   migration directory (Article III's check).
2. **Fix the compile fallout of step 1** before adding anything: `movies.service.ts` (lines 58, 72,
   291, 295, 360), `movies/entities/movies.entity.ts:37`, `movies/dto/create-movie.dto.ts:47`,
   `uploads.service.ts:212` and `:232`, `media-sources.service.ts:14-23`. The last one is the field
   the **worker** reads — `findOneFlat` must keep returning `movieId` with the same name and type;
   it just stops being derived.
3. **Torrent client.** `types.ts` first, then `client.ts`: the four new/changed methods, the 5.0
   state sets (`stoppedDL`, `stoppedUP`, `forcedMetaDL` at minimum), the `response.ok` checks, and
   an unrecognised state that no longer becomes `ERROR`.
4. **Tag building.** One small private helper per acquisition service, producing the tag list from
   the title (REQ-5's comma/whitespace sanitisation, with the id-derived fallback) and, for
   episodes and seasons, the English `Season <n>` / `Episode <n>` — unpadded. Pass it into
   `qbittorrent.add()`.
5. **Retire `force`.** Remove the `@Args('force', …)` from all five resolvers, the argument from
   the five service signatures, the three `ConflictException`s, the two `updateMany` demote blocks
   in `episodes`/`seasons`, and the two 409s in `uploads.service.ts`. Keep every cross-title
   `infoHash` collision check exactly as it is.
6. **`downloads/` surface.** `Download` entity, then the two queries (ownership clause → sibling
   `media_sources` by target → one `info(tag)` call → join on `infoHash` → ×100 on `progress`),
   then the three mutations. A source with no `infoHash` is refused with
   `Esa descarga no es un torrent` before any client call. A torrent absent from the client yields
   null live fields, never a dropped row.
7. **Race arbiter.** In `handleTorrentCompleted`, after the self-idempotency rung and before the
   `ERROR` rung: if any *other* source of the same target is already `READY` or `SCANNED`, log and
   return, changing nothing. On the success path, after the existing transaction, stop every other
   non-terminal sibling in the client and move it to `PAUSED` — the winner is left running.
8. **Loser sweep.** In `downloadRemove`, after the winner's `torrentClient.remove`: select siblings
   by `movieId`/`episodeId`/`seasonId`, `remove(hashes, true)`, then `deleteMany` those rows.
9. **Tests** (below), then the typecheck and suite.

## Contract obligations

`api` is the producer of everything in `../spec.md` § GraphQL Contract Delta. Exactly that SDL must
appear in the regenerated `src/schema.gql` — Article VIII's check is a diff of the two.

Beyond the SDL:

- Every message in the spec's error table, byte-for-byte. Only two are new
  (`Esa descarga no es un torrent`, `qBittorrent rechazó la operación (<status>)`); the rest already
  exist in `src/` and must be reused, not retyped from the spec.
- The three `… ya tiene una descarga en curso. Confirmá para reemplazarla.` strings are **deleted**,
  including both upload copies. `web` deletes its substring matchers in the same delivery.
- No `@AllowService()` on any of the five new operations.
- `downloadRemove` and `sourceScanned` keep their exact signatures. The worker is not in
  `services:`.

## Tests

Two units here can fail with no error anywhere, and both are named in `spec.md` NFR-5. Each file
opens with a comment stating the failure class, per Article IX, and each case is written by fault
injection — verify it fails when the rule is removed.

- **`src/downloads/downloads.service.spec.ts`** (new) — defends against **a second source of the
  same target reaching `ENCODING`**. A `torrentCompleted` for a loser whose sibling is already
  `READY` must change nothing and enqueue nothing; remove the guard and the case must fail. Also
  covers that the winner is *not* stopped while its siblings are, and that a paused loser lands on
  `PAUSED` rather than `ERROR` — `ERROR` would be read by this very function as "superseded".
- **`src/process-jobs/process-jobs.service.spec.ts`** (extend) — defends against **the sweep
  selecting siblings by tag rather than by target id**. A second title whose tag string collides
  must keep its downloads; switch the selection to a tag match and the case must fail. Also assert
  the winner's `deleteFiles: false` and the losers' `true` are not swapped.

Not owed a test: the tag builder (a pure string function whose output is visible in qBittorrent and
covered by AC-1 to AC-3 — a bug here is loud, not silent), the new client methods (thin `fetch`
wrappers; their failure mode is the `response.ok` check, exercised live by AC-17), and the
`downloads` queries' ownership clause — that one is *not* silent, it returns a visible exception,
and `movies.service.spec.ts` already covers the identical clause it copies.
