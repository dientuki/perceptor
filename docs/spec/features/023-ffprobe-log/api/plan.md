# PLAN: ffprobe Log — `api` (`api/plan.md`)

## Scope

This service owns the `FfprobeLog` model, its migration, and all four GraphQL operations in
`../spec.md` § GraphQL Contract Delta. It stores the payload the worker sends as an opaque string —
it never parses it, never validates it as JSON, never inspects streams. It also owns the two new
error keys and their English templates.

It does **not** call `ffprobe`, decide when a probe happens, or know which `ProcessJob` a row
belongs to: the worker owns all of that, and `../spec.md` deliberately gives the model no relation
to any other table.

Writes are confined to `services/api/` and this directory. Anything else is a stop-and-report.

## Existing code to reuse

- `src/process-jobs/process-jobs.resolver.ts` — the shape to copy for a resolver the worker calls:
  plain `@Args('id', { type: () => Int })` scalars, `@AllowService()` per method, no DTO class for
  a two-scalar mutation. Do not add a `dto/` directory for this slice.
- `src/auth/decorators/allow-service.decorator.ts` — the machine-credential carve-out. Goes on
  `recordFfprobe` and on nothing else here.
- `src/auth/guards/admin.guard.ts` — applied with `@UseGuards(AdminGuard)` on
  `ffprobeLogs`, `ffprobeLog` and `deleteFfprobeLog`, **method by method**. Do **not** copy
  `UsersResolver`'s class-level placement: `AdminGuard` throws for any principal whose
  `type !== 'user'`, so at class level it would reject the worker's `SERVICE_TOKEN` on
  `recordFfprobe`, and the worker swallows that error by design — the table would silently stay
  empty (`../plan.md` § Risks, first row).
- `src/auth/guards/jwt-auth.guard.ts` — already `APP_GUARD`; it is what rejects a service principal
  on the three admin operations, so no extra code is needed for that half of NFR-2.
- `src/i18n/i18n-error.ts` — `i18nError.notFound(...)` / `i18nError.badRequest(...)`. Never
  `new NotFoundException(...)` directly; the factory is what puts `i18n` on the wire.
- `src/i18n/error-keys.ts` + `src/i18n/messages.en.ts` — the two new keys go in both. Adding a key
  with no template fails `src/i18n/messages.en.spec.ts`, and an orphaned template fails it too;
  that suite is the existing guard for this and needs no extension.
- `src/prisma/prisma.service.ts` — injected as every other service injects it.
- `src/media-sources/` or `src/settings/` — reference for a service method that is a thin Prisma
  call with one guard clause. Keep the same weight; this slice has no business logic to speak of.

## Steps

1. Add `model FfprobeLog` to `prisma/schema.prisma`: `id Int @id @default(autoincrement())`,
   `file String @db.VarChar(500)`, `ffprobe String @db.MediumText`,
   `createdAt DateTime @default(now())`, `@@index([file])`, `@@map("ffprobe_logs")`. No relations,
   no `updatedAt` — rows are immutable (REQ-2).
2. Generate the migration with `bin/npm api run prisma:migrate`, named `add_ffprobe_logs`. Confirm
   the generated SQL says `MEDIUMTEXT` for `ffprobe`, not `TEXT`.
3. Add `FFPROBE_LOG_NOT_FOUND: 'error.ffprobeLog.not_found'` and
   `FFPROBE_LOG_EMPTY_PAYLOAD: 'error.ffprobeLog.empty_payload'` to `ERROR_KEYS`, and their English
   templates to `MESSAGES_EN` — the exact strings in `../spec.md`'s error table, `{id}` included.
4. Write `entities/ffprobe-log.entity.ts`: `@ObjectType()` with `id: number` (`@Field(() => Int)`),
   `file: string`, `ffprobe: string`, `createdAt: Date`. Field names and nullability come from the
   frozen SDL — all four non-null.
5. Write `ffprobe-logs.service.ts`:
   - `record(file, ffprobe)` — rejects an empty or whitespace-only `file` or `ffprobe` with
     `i18nError.badRequest(ERROR_KEYS.FFPROBE_LOG_EMPTY_PAYLOAD)`, then `prisma.ffprobeLog.create`.
   - `findAll(file?, take, skip)` — `where` only when `file` is given (exact equality, no `contains`),
     `orderBy: [{ createdAt: 'desc' }, { id: 'desc' }]`, `take`, `skip`.
   - `findOne(id)` — `findUnique`, throwing `i18nError.notFound(ERROR_KEYS.FFPROBE_LOG_NOT_FOUND, { id })`
     on a miss. It returns `FfprobeLog!`, never null.
   - `remove(id)` — `findOne(id)` first so a missing row produces the keyed `not_found` rather than
     a raw Prisma `P2025`, then `delete`, returning `true`.
6. Write `ffprobe-logs.resolver.ts` with the four operations and the guard split from § Existing
   code to reuse. `take`/`skip` carry `defaultValue: 50` / `defaultValue: 0` so the generated SDL
   matches the frozen delta exactly.
7. Register `FfprobeLogsModule` in `src/app.module.ts`.
8. Boot once and diff `src/schema.gql` against `../spec.md` § GraphQL Contract Delta. Any
   difference is a bug in this slice, not in the spec (Constitution, Article VIII).

## Contract obligations

Exactly the SDL in `../spec.md` § GraphQL Contract Delta, and the four error rows in its table:
`error.ffprobeLog.not_found` with `{ id }` on both `ffprobeLog(id)` and `deleteFfprobeLog(id)`;
`error.ffprobeLog.empty_payload` with no params on `recordFfprobe`; `error.auth.admin_required` and
`error.auth.unauthenticated` from the existing guards, unchanged and not re-keyed.

`ffprobeLogs` orders newest-first and filters `file` by exact equality. `recordFfprobe` returns the
created row even though its only caller discards it. The delta is read-only — if it is wrong, stop
and report.

## Tests

- `src/ffprobe-logs/ffprobe-logs.resolver.spec.ts` — **owed** (Article IX). The failure it defends
  against is the silent one from `../plan.md` § Risks: `AdminGuard` reaching `recordFfprobe`, or
  `@AllowService()` leaking onto a read. The worker swallows an auth rejection by design, so this
  miswiring produces an empty table and no error anywhere. Assert it by reading the metadata Nest
  actually sees — `Reflector.get(ALLOW_SERVICE_KEY, …)` and `Reflect.getMetadata('__guards__', …)`
  — per method, not by calling the resolver. Open the file with the header paragraph Article IX
  requires.
- `src/ffprobe-logs/ffprobe-logs.service.spec.ts` — **owed**, narrowly: `remove` on a missing id
  must produce `error.ffprobeLog.not_found` and not a raw Prisma error (a raw `P2025` reaches the
  caller with no `i18n` extension, which is exactly the un-keyed error `018-ui-i18n` exists to
  prevent), and `findAll` must order `createdAt` **desc** — an ascending order silently returns the
  oldest probe as "the latest", which is wrong in the one way nobody notices. Fault-inject both per
  the house technique in `services/api/CLAUDE.md` § Tests.
- `src/i18n/messages.en.spec.ts` — **not extended.** It already iterates `ERROR_KEYS`, so the two
  new keys are covered the moment they are added.
- `record`'s happy path and the entity decorators are **not owed** tests: a broken `create` or a
  missing `@Field` fails loudly at the first call, and the schema diff in step 8 covers the shape.
