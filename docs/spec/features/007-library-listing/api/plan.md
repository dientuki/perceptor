# PLAN: Library Listing for Movies and Shows — `api` (`api/plan.md`)

## Scope

This slice adds the read side for series: a `Show` GraphQL type, a `shows` query scoped to the
calling user, a `ShowsService.findAll(userId)` behind it, and the migration that turns
`Show.status` into the `MediaStatus` enum. It also owns the regenerated `schema.gql`.

It does **not** touch films. `MoviesService`, `MoviesResolver`, `Movie` and the `movies` query come
out of this feature byte-identical (spec REQ-7, NFR-3) — if a change to any of them seems necessary,
stop and report. It does not touch `MediaTypeService` or `MediaDispatchService`: listing is
deliberately not parameterized by media type. It does not render anything; `/shows` belongs to
`web`.

Writes are confined to `services/api/` and this directory. Anything else is a stop-and-report (see
`.claude/agents/api.md`).

  the order; **drop the `include`** — `Show` has no `mediaSource` or `processJobs`, and seasons are

- `services/api/src/movies/entities/movies.entity.ts` — the field-decorator conventions: `@Field(() => ID)`

## Steps

1. **Schema**: change `Show.status` in `prisma/schema.prisma` from `String?` to
   `MediaStatus @default(MISSING)`. Leave every other field on `Show` alone.
2. **Migrate**: `bin/npm api run prisma:migrate`, naming it `add_show_status_enum`. Then **open the
   generated `migration.sql` and read it.** It must set existing rows to `MISSING` before (or as
   part of) making the column `NOT NULL`. If Prisma generated a bare `MODIFY ... NOT NULL` with no
   backfill, add the `UPDATE shows SET status = 'MISSING' WHERE status IS NULL;` ahead of it in the
   generated file — that is editing a migration you just generated and have not applied elsewhere,
   which is fine; hand-written SQL against the *running database* is what Article III forbids.
3. **Verify the data**: `bin/mysql -e 'select status, count(*) from shows group by status'` — every
   row `MISSING`, zero NULLs (AC-9).
4. **Entity**: create `src/shows/entities/show.entity.ts` with exactly the fields in `../spec.md`
   § GraphQL Contract Delta — `id: ID!`, `tmdbId: Int!`, `title: String!`, `overview: String`,
   `posterUrl: String`, `releaseDate: DateTime`, `originalLanguage: String!`, `isLiveAction: Boolean!`,
   `status: String!`, `seasonsSyncedAt: DateTime`, `createdAt: DateTime!`, `updatedAt: DateTime!`.
   `status` is a TypeScript `string` and a bare `@Field()` — not the Prisma enum type, not
   `registerEnumType`.
5. **Service**: add `findAll(userId: string)` to `ShowsService`. One `findMany`, filter through
   `users: { some: { userId } }`, `orderBy: { createdAt: 'desc' }`. One query, no per-row lookup
   (NFR-1). Place it near the top of the class with the other public methods; it is unrelated to
   the hydration machinery below it.
6. **Resolver + module**: create `ShowsResolver` with the single `shows` query, add it to
   `ShowsModule`'s `providers`, and add `ShowsModule` to `app.module.ts`'s `imports`. That last one
   is *not* strictly required — `MediaModule` already imports `ShowsModule`, so the resolver would
   be discovered either way — but every other domain module is listed in `app.module.ts` and
   `services/api/CLAUDE.md` states that as a fact. Keeping it true is cheaper than the next reader
   discovering the exception.
7. **Regenerate and inspect**: boot the service and diff `src/schema.gql`. It must gain the `Show`
   type and `shows: [Show!]!` and nothing else (AC-13). If `Movie` or `movies` moved, something in
   step 4 was wrong.
8. **Tests**: extend `shows.service.spec.ts` (see Tests below).
9. **Report the counts**: `bin/cli api npx --no tsc --noEmit` (expected 0, the baseline) and
   `bin/npm api test` (expected 84 + the new cases) before and after, per this service's convention.

## Contract obligations

`../spec.md` § GraphQL Contract Delta is read-only. What this service owes:

- `shows: [Show!]!` — a list, never null, empty for a user with no series (spec REQ-4). Returning
  `null` for an empty library is a contract violation the typechecker will not catch on the consumer
  side; it surfaces as a GraphQL non-null error in `web`.
- `Show.status` as **`String!`** even though the column is now an enum. This is the point that will
  feel wrong from inside this service. `Movie.status` already crosses this way and `web`'s `Movie`
  type declares `status: string`; a GraphQL enum for `Show` alone would make the two listings
  structurally different in the one place the spec keeps them identical. Do not `registerEnumType`.
- `Show.seasonsSyncedAt` nullable, and no `type` field, and no `seasons`. All three are deliberate;
  see `../plan.md` § Contract Freeze.
- The service principal gets `[]`, not an exception (spec REQ-5, AC-6).
- `movies`, `movie(id)`, `Movie`, `searchMedia`, `addMedia` unchanged.

If the contract is wrong, stop and report — do not adapt it locally (Article VIII).

## Tests

- `src/shows/shows.service.spec.ts` — **owed**, extend the existing suite. The failure it defends
  against: `findAll` returning series the caller does not own. That produces no error anywhere — the
  query succeeds, the page renders, the cards are real series — and it is a cross-user data leak.
  At minimum:
  - a case asserting the `prisma.show.findMany` call carries `where: { users: { some: { userId } } }`
    with the caller's id, which fails if the filter is dropped or hardcoded;
  - a case asserting `orderBy: { createdAt: 'desc' }` (spec REQ-3);
  - a case asserting an empty result comes back as `[]` (spec REQ-4).

  Follow the existing file's mocking style (`prisma.show.findMany.mockResolvedValue(...)`), and give
  the new `describe` block a header comment naming the leak, per Article IX and this service's
  convention.

- `ShowsResolver` — **not owed a test**. Its whole body is the `principal.type === 'user'`
  narrowing plus a delegation, mirroring `MoviesResolver`, which has no spec either. The behaviour
  that matters (a service principal getting an empty list) is covered end to end by AC-6 against the
  running API, which is a stronger check than a mocked resolver unit.

- The migration — **not owed a unit test**; AC-9 queries the real rows, which is the only check that
  means anything for a backfill.
