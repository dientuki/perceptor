# PLAN: Per-Title Audio/Subtitle Language Split — `api` (`api/plan.md`)

## Scope

`api` owns everything that has a name in this feature: the Prisma migration that adds `kind` to the
two per-title join tables, the per-kind read/write pair in `LanguagesService`, the four renamed
GraphQL fields and two renamed mutations, and the encode merge that now produces two allow-list pairs
instead of one.

It also owns the `0.2.0` *Audio mandatory* flag end to end on this side: three boolean columns, one
field on each of `UserPreferences`/`Movie`/`Show`, and three mutations. The flag is **inert** — no
merge reads it, no payload carries it (REQ-11). Resist completing it.

It does **not** touch the installation `default_languages` setting, `UserLanguagePreference`'s rows,
or the language half of `Query.preferences` (NFR-4) — those keep their current behaviour, including
the unsplit contribution `default_languages` makes to both allow-lists. `UserPreferences` gains one
boolean field and nothing else. It does not touch `web` or
`worker`; both consume this slice's output and are their own tasks.

Writes are confined to `services/api/` and this directory. Anything else is a stop-and-report.

## Existing code to reuse

- `services/api/src/languages/languages.service.ts` — `setPreferredTrackLanguagesFor` /
  `findPreferredTrackLanguagesFor` are the per-kind write and read this slice mirrors: validate the
  whole tag list first, then `deleteMany` narrowed by `kind` + `createMany`, both inside one
  `$transaction`. Do not introduce a different write shape for the per-title level.
- `validateAndResolveLanguageIds` in the same file — the whole-list-validated-before-any-write check
  every language mutation already shares. Both new mutations go through it unchanged; do not add a
  second validator.
- `services/api/src/preferences/entities/language-track-kind.enum.ts` — the `LanguageTrackKind`
  GraphQL enum is already registered here by `021-user-preferences`. Import it in the movies and
  shows resolvers; **never** call `registerEnumType` a second time (a duplicate registration fails
  schema generation).
- `services/api/src/preferences/preferences.resolver.ts`'s `setPreferredTrackLanguages` — the exact
  `@Args('kind', { type: () => LanguageTrackKind })` + `kind as unknown as PrismaLanguageTrackKind`
  cast to use at the resolver boundary.
- `MoviesService.findOneFromDb` / `ShowsService.findOneFromDb` — already return `null` for both a
  missing id and an unowned title. The existing `i18nError.notFound(ERROR_KEYS.MOVIE_NOT_FOUND, …)` /
  `ERROR_KEYS.SHOW_NOT_AVAILABLE` throws in the two mutations move over verbatim (REQ-4).
- `services/api/src/users/users.service.ts`'s `setAllowCinemaReleases` (line 221) — a three-line
  `prisma.user.update`. `setAudioMandatory` is its twin; do not route the new flag through a
  different layer.
- `PreferencesService.setAllowCinemaReleases` + `PreferencesResolver.setAllowCinemaReleases` — the
  full path a per-user boolean already takes: resolver rejects a non-user principal, service
  delegates to `UsersService`, then returns `findForUser`. `setAudioMandatory` follows it exactly,
  returning `UserPreferences` for the same reason.
- `MoviesService`/`ShowsService`'s existing `prisma.userMovie.upsert` / `prisma.userShow.upsert`
  (movies.service.ts line 169, shows.service.ts line 249) — these services already own the ownership
  join, so the per-title flag's read and write live there, **not** in `LanguagesService`. The flag is
  not a language row.
- `ProcessJobsService.collectAllowedLanguages` — the single walk that produces the iso3 list and the
  tag list together. Extend it; do not add a second merge helper beside it.

## Steps

1. `schema.prisma`, **both edits before generating anything** so the feature has one migration:
   (a) add `kind LanguageTrackKind @default(AUDIO)` to `UserMovieLanguage` and `UserShowLanguage`,
   extending each `@@id` to `[userId, movieId, languageId, kind]` / `[userId, showId, languageId,
   kind]`; (b) add `audioMandatory Boolean @default(false)` to `User` (beside `allowCinemaReleases`),
   `UserMovie` and `UserShow`. Then run `bin/npm api run prisma:migrate`, naming the migration
   `add_title_language_kind`. Read the generated SQL and confirm it adds the `kind` column with
   `DEFAULT 'AUDIO'`, rewrites both primary keys, and adds the three boolean columns with
   `DEFAULT false`.
2. `languages.service.ts`: give `setMoviePreferredLanguagesFor`/`findMoviePreferredLanguagesFor` and
   the two show twins a `kind: LanguageTrackKind` parameter. Narrow both `deleteMany` `where` clauses
   to include `kind`, add `kind` to each `createMany` row, and add `kind` to both `findMany` `where`
   clauses. Rename the four methods to `…PreferredTrackLanguagesFor` to match the mutations, keeping
   the movie/show pair separate (`006-media-search` § Out of Scope keeps these twins apart on
   purpose).
3. `movies.entity.ts` / `show.entity.ts`: replace the `preferredLanguages` field with
   `audioLanguages` and `subtitleLanguages`, both `[Language!]!`.
4. `movies.resolver.ts` / `shows.resolver.ts`: replace the single `@ResolveField` with two, each
   calling the read with its own `kind`. Keep the "only runs when selected" comment's intent — the
   listing queries must still not select these (two field resolvers make an unselected listing
   twice as expensive if `web` ever selects them there).
5. Same two files: rename the mutation to `setMoviePreferredTrackLanguages` /
   `setShowPreferredTrackLanguages`, add the `kind` argument between the id and `tags`, and keep the
   ownership check and its existing throw exactly as they are. Neither carries `@AllowService()`.
6. `encode-job-details.entity.ts`: replace `allowedLanguagesIso3`/`allowedLanguageTags` with the four
   fields from `../spec.md` § GraphQL Contract Delta.
7. `process-jobs.service.ts`: add `kind` to the `languages` select in `mergeMovieAllowedLanguages` /
   `mergeShowAllowedLanguages`, and turn `collectAllowedLanguages` into one walk over four Sets — the
   original language and every `default_languages` entry seed **both** pairs; each owner preference
   seeds only the pair matching its `kind`. Both `getEncodeJobDetails` branches spread the four
   fields onto the payload.
8. Update the two block comments that describe the old single list (`collectAllowedLanguages`'s
   header and `EncodeJobDetails`'s field comments) so they describe what the code now does. Article XI
   still applies to anything new: no new explanatory comments beyond the test header in step 9.
9. The flag's per-user path: `UsersService.setAudioMandatory` (twin of `setAllowCinemaReleases`),
   `audioMandatory` on `UserPreferences`, read in `PreferencesService.findForUser`'s existing
   `Promise.all` destructuring, written by `PreferencesService.setAudioMandatory`, exposed as
   `PreferencesResolver.setAudioMandatory(mandatory: Boolean!): UserPreferences!` with the same
   non-user-principal rejection every operation in that resolver already has.
10. The flag's per-title path: a `@ResolveField(() => Boolean) audioMandatory` on each of the movie
    and show resolvers, reading the caller's `user_movies`/`user_shows` row through a new
    `MoviesService`/`ShowsService` method; and `setMovieAudioMandatory(movieId, mandatory)` /
    `setShowAudioMandatory(showId, mandatory)` returning `Boolean!`, each reusing the **same**
    `findOneFromDb` null-check and throw as the language mutation beside it (REQ-10). A row that
    passes that check is guaranteed to exist, so the write is an `update`, not an `upsert`.
11. Tests, per § Tests below.
12. `services/api/CLAUDE.md`: update the `languages/` and `process-jobs/` descriptions and any
    sentence claiming one list serves both audio and subtitles at the per-title level.

## Contract obligations

From `../spec.md` § GraphQL Contract Delta, read-only:

- `Movie.audioLanguages`, `Movie.subtitleLanguages`, `Show.audioLanguages`, `Show.subtitleLanguages`
  — all `[Language!]!`, resolving to the **calling user's own** set for that title and kind, never
  the merge across owners.
- `setMoviePreferredTrackLanguages(movieId: Int!, kind: LanguageTrackKind!, tags: [String!]!)` and
  `setShowPreferredTrackLanguages(showId: Int!, kind: LanguageTrackKind!, tags: [String!]!)`, both
  returning `[Language!]!` — the freshly stored set for that kind.
- `EncodeJobDetails.allowedAudioLanguagesIso3`, `allowedAudioLanguageTags`,
  `allowedSubtitleLanguagesIso3`, `allowedSubtitleLanguageTags` — all `[String!]!`, all
  original-first and deduplicated, none ever empty.
- The four error conditions in `spec.md`'s table, unchanged: `LANGUAGE_UNAVAILABLE`,
  `LANGUAGE_DUPLICATE`, `MOVIE_NOT_FOUND`/`SHOW_NOT_AVAILABLE`, `AUTH_UNAUTHENTICATED`.
- `UserPreferences.audioMandatory: Boolean!`, `Movie.audioMandatory: Boolean!`,
  `Show.audioMandatory: Boolean!` — the last two resolving to the **calling user's own** flag for that
  title, read off the ownership row.
- `setAudioMandatory(mandatory: Boolean!): UserPreferences!`,
  `setMovieAudioMandatory(movieId: Int!, mandatory: Boolean!): Boolean!`,
  `setShowAudioMandatory(showId: Int!, mandatory: Boolean!): Boolean!` — return types are not
  interchangeable: the first returns the whole preferences object like `setAllowCinemaReleases`, the
  per-title pair returns the stored boolean.
- **Nothing about the flag reaches `EncodeJobDetails`** (REQ-11). Adding it there is a contract
  change, not a completion.
- Removed with no replacement kept alongside: `Movie.preferredLanguages`, `Show.preferredLanguages`,
  `setMoviePreferredLanguages`, `setShowPreferredLanguages`,
  `EncodeJobDetails.allowedLanguagesIso3`, `EncodeJobDetails.allowedLanguageTags`.

`web` and `worker` retype every one of these names by hand. A name that differs from the delta by a
character compiles here and fails at runtime there.

## Tests

- `services/api/src/languages/languages.service.spec.ts` — **owed** (NFR-3). Both per-title tables
  now hold two kinds keyed apart only by `kind`; a `deleteMany` left at `{ userId, movieId }` wipes
  the caller's subtitle set on every audio save and reports success. Add one case per table, in the
  shape of the existing `setPreferredTrackLanguagesFor` case at line 148: write `AUDIO`, assert the
  `where` carries `kind`, then write `SUBTITLE` and assert the same. Verify by fault injection —
  widen the `where` back to drop `kind`, watch the test fail, restore it — and say so in the `it`
  string, as that existing case does. The existing per-title `targets` table also needs `kind`
  threading through its `expectedDeleteWhere`/`expectedCreateRow`.
- `services/api/src/process-jobs/process-jobs.service.spec.ts` — **owed**. Two silent failures live
  here: a merge that filters the original language or `default_languages` by kind (the subtitle list
  quietly loses the installation default for every title), and one that applies an owner's preference
  to both pairs (the split never reaches FFmpeg). Add the AC-8 case (no per-title preference of
  either kind → both pairs identical to what the single list produced) and the AC-9 case (an
  audio-only `fr` preference → `fre` in the audio pair, absent from the subtitle pair). The `owner`
  fixture at line 120 needs a `kind` per language row.
- The resolvers themselves are **not owed** a test: the ownership refusal they add is one `if` over
  `findOneFromDb`'s existing null, unchanged from the mutations they replace, and it fails loudly.
- The `audioMandatory` flag is **not owed** a test, and this is a real judgement rather than an
  omission (Article IX). Each of its three writes is a single-column `update` on a row addressed by
  its full primary key: there is no replace-all, no `deleteMany` that could over-reach, no validation
  to run in the wrong order, and no second store to disagree with. Nothing reads it, so it cannot
  produce a wrong result anywhere — the worst failure available is "the checkbox does not come back
  ticked", which is loud, immediate and covered by AC-11/AC-12/AC-13's manual pass. The test becomes
  owed the day a rule consults the flag; that is the same day `getAudioParams` reopens.
