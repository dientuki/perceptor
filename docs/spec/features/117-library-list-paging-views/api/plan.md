# PLAN: Library list paging, list view and possession filter — `api` (`api/plan.md`)

## Scope

`api` exposes one page of the caller's films or series with the counts a pager needs
(`moviePage`/`showPage`), filtered by possession, and stores on every series the audio/subtitle
languages shared by all its downloaded episodes, kept fresh on every write of an episode's file
languages and backfilled at boot. It does **not** render anything, read URL or cookie state, or
change `movies(isShort)`/`shows` in any way (NFR-2) — paging state and its normalization are `web`'s.

Writes are confined to `services/api/` and this directory.

## Existing code to reuse

- `MoviesService.findAll` / `ShowsService.findAll` — the ownership `where` (`users: { some: { userId } }`)
  and `isShort` handling (`isShort === undefined ? {} : { isShort }`). Copy the clause exactly; do
  **not** copy `findAll`'s `include: { mediaSources, processJobs }` (plan § Approach).
- `MoviesService.withDerivedStatus` — still apply it to each row so `status` keeps the same `string`
  typing as `movies`; it is a pass-through since `089`.
- `MoviesResolver.getMovies` / `ShowsResolver.getShows` — the principal narrowing
  (`principal.type === 'user' ? principal.id : ''`), so a service token gets an empty page, not
  everyone's library.
- `library-probe/library-probe.resolver.ts` — `asLanguages` and the `FILE_*_DESCRIPTION` constants;
  `ShowLibraryTracksResolver` uses `asLanguages` with the spec's own descriptions (they differ from
  `108`'s wording).
- `LibraryProbeService.onApplicationBootstrap` — the detached `void … .catch(logger.warn)` pattern
  for the backfill.
- `media-server-reconcile.service.ts`'s `CLEARED_TRACKS` and `Prisma.DbNull` — write a `null` series
  value with `Prisma.DbNull`, not `null`, or Prisma writes JSON `null` instead of SQL `NULL`.
- `media/entities/content-kind.enum.ts` — the `registerEnumType` shape for `LibraryPossession`.

## Steps

1. Schema + migration: add the two `Show` columns; `bin/npm api run prisma:migrate` with a name
   ending `show_file_track_languages`; `prisma:generate`.
2. `show-track-languages/intersect.ts`: `intersectEpisodeLanguages(episodes)` where each episode is
   `{ seasonNumber, tracksReadAt, fileAudioLanguages, fileSubtitleLanguages }`. In scope =
   `seasonNumber !== 0 && tracksReadAt !== null`. No episode in scope → `{ audio: null, subtitles: null }`.
   Otherwise each list is the set of codes present in every in-scope episode's list, sorted
   alphabetically (a series has no single "file order" to preserve). An in-scope episode whose list
   is not an array counts as `[]`.
3. `ShowTrackLanguagesService.recompute(showId)`: one `episode.findMany` (select the four fields via
   `season.seasonNumber`) + one `show.update`, writing `Prisma.DbNull` for `null`. Wrapped: any error
   is logged with the show id and swallowed (NFR-6) — `recompute` never throws. A deleted show is a
   logged no-op.
4. `onApplicationBootstrap`: detached; `show.findMany({ select: { id } })`, then `recompute` each,
   sequentially (NFR-5). No queue, no worker job, no media-server call.
5. `LibraryProbeService.completed`: after the `updateMany`, when the target is an episode and
   `count === 1`, look up its `season.showId` and `await recompute(showId)`. The return value of
   `completed` is unchanged. Import `ShowTrackLanguagesModule` into `LibraryProbeModule`.
6. `MediaServerReconcileService.syncShow`: after the write loop, when `demoted > 0`,
   `await recompute(showId)`. A promotion does not need it (it queues a probe, whose `completed`
   recomputes). Import the module into `MediaServerModule`. Check no other code path clears an
   episode's `fileAudioLanguages` (`grep -rn "CLEARED_TRACKS\|fileAudioLanguages" src`); if one
   exists, stop and report rather than adding a third call site silently.
7. `ShowLibraryTracksResolver` on `Show`: `fileAudioLanguages`/`fileSubtitleLanguages`, nullable
   `[String]`, descriptions verbatim from spec § GraphQL Contract Delta.
8. `media/library-page.ts`:
   - `PAGE_SIZES = [12, 24, 48, 96]`, `DEFAULT_PAGE_SIZE = 24`; `clampPageSize(n)` → `n` if in the set,
     else 24.
   - `totalPages(totalCount, pageSize) = max(1, ceil(totalCount / pageSize))`;
     `clampPage(page, totalPages) = min(max(1, page), totalPages)`.
   - `possessionWhere(p)`: `ALL` → `{}`, `DOWNLOADED` → `{ status: 'COMPLETED' }`,
     `ADDED` → `{ status: { not: 'COMPLETED' } }`.
   - `LIBRARY_ORDER = [{ createdAt: 'desc' }, { id: 'desc' }]`.
9. `LibraryPossession` enum, `MoviePage`/`ShowPage` object types (`items`, `totalCount`, `page`,
   `pageSize`, `totalPages`; descriptions from the spec).
10. `MoviesService.findPage` / `ShowsService.findPage`: build `where` (ownership + `isShort` for films
    + possession), `count`, clamp size then page, `findMany({ where, orderBy: LIBRARY_ORDER,
    skip: (page - 1) * pageSize, take: pageSize })`. Two queries, no `include`.
11. Resolvers: `moviePage(isShort: Boolean, possession: LibraryPossession! = ALL, page: Int! = 1,
    pageSize: Int! = 24)` and `showPage(...)` exactly as the SDL in the spec. No `@AllowService()`.
12. Boot, open the playground, confirm the generated `src/schema.gql` matches the spec's SDL
    (names, nullability, defaults, descriptions). Any difference is a stop-and-report.

## Contract obligations

Exactly the SDL in `../spec.md` § GraphQL Contract Delta: the `LibraryPossession` enum, `MoviePage`,
`ShowPage`, the two `Show` fields and the two queries with their defaults. Error behaviour:

- No session → the existing global guard error (unchanged).
- Service token → resolves an empty page (`items: []`, `totalCount: 0`, `page: 1`, `totalPages: 1`)
  through the `''` user id, the same posture `movies`/`shows` have.
- Invalid enum → schema validation (nothing to write).
- `page`/`pageSize` out of range → clamped, never thrown; the response carries the clamped values.

## Tests

- `src/media/library-page.spec.ts` — defends against a pager that silently repeats/drops titles or
  shows an empty page for a non-empty library. Cases: `clampPageSize(7) === 24`; `clampPage(0) === 1`;
  `clampPage(99, 2) === 2`; `totalPages(0, 24) === 1`; `possessionWhere('ADDED')` matches `ERROR`,
  `MISSING`, `DOWNLOADING` and not `COMPLETED` (assert the object, then fault-inject `MISSING`-only);
  `LIBRARY_ORDER` ends in `id` (fault-inject its removal).
- `src/show-track-languages/intersect.spec.ts` — defends against a series column that lies with no
  error. Cases: AC-7's 28/28 + 25/28 shape; season 0 ignored; unread episode (`tracksReadAt: null`)
  ignored; no episode in scope → both `null`; in-scope episodes with no common code → `[]`; output
  sorted.
- `src/show-track-languages/show-track-languages.service.spec.ts` — `recompute` writes `DbNull` for
  `null` (not JSON null) and swallows a Prisma failure (NFR-6).
- Extend `src/library-probe/library-probe.service.spec.ts` — `completed` for an episode calls
  `recompute` with its show id on `count === 1`, not on a stale report (`count === 0`), and not for a
  movie. Fault-inject by removing the call.
- Extend `src/media-server/media-server-reconcile.service.spec.ts` — `syncShow` that demotes calls
  `recompute(showId)`; one that only promotes does not.
- `movies.service.spec.ts` / `shows.service.spec.ts`: one case each that `findPage` passes the
  clamped `skip`/`take`, the ownership `where` and `LIBRARY_ORDER` to Prisma, and returns the clamped
  `page`. Dropping the ownership clause must fail it (it would leak other users' titles with no error).

Not owed: the entity and enum files (declarative); the resolvers beyond the service tests (thin
delegation, same as `movies`/`shows`).
